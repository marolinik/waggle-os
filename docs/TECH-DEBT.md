## Debt Budget & Broken-Windows Policy

Ratified 2026-09-18 (Phase 6). **Boy Scout plus ticket-or-fix**, deliberately not a fixed
percentage: arcs here range from a one-line fix to a multi-session benchmark, so a flat 20%
would be arbitrary in both directions.

1. **A window you touch, you close.** If a change puts you inside a defect — a duplicated rule,
   a silent catch, a stringly-typed contract — fix it in the same arc, or give it a Debt Ledger
   row with an ID, location, risk, effort, priority and owner **before the PR merges**.
2. **No untracked hacks.** A bare `// TODO` with no ID is not allowed to land. Either it cites a
   ledger ID or a tracked ticket, or it is not a TODO — it is unfinished work.
   *Measured 2026-09-18: `packages/{server,agent,core,shared}/src` carry* **zero** *untracked
   markers. Of 15 hits, 13 are regex literals inside detectors (`evolution-gates.ts`,
   `session-utils.ts`) and the 2 real ones each cite a ticket (`FR-2`, `M-05`).* This row records
   a property the repo already has; the job is keeping it.
3. **Phases pay the interest, arcs pay the principal they create.** A `/remove-technical-debt`
   phase is for debt nobody is currently standing in. It is not a licence for feature arcs to
   defer their own mess to it.
4. **A wrong ledger row is a defect.** Rows drift as the code moves. Correcting or splitting one
   is a legitimate outcome of a phase — CA-5 lost its `CredentialPool` half and gained CA-5b that
   way, and TD-TEST-5's "three shapes" had converged to two. A stale row costs the next reader
   more than an open one.

## Adopted Conventions

- A chat request rejection is built by `rejectChatRequest` at module scope in `chat.ts`, never
  assembled inline. The helper supplies status, message and code; it never invents a body shape.
  (Phase 6, TD-CHAT-18 — ratified as a convention in Phase 3, consumed 2026-09-18.)
- The server suite parses SSE through `parseSSE` / `parseSseJson` in `tests/test-utils.ts`. A
  private copy in a test file is duplicated knowledge, however small. (Phase 6, TD-TEST-5.)
- A layer boundary is held by **two** mechanisms, not one: a guard test that walks the transitive
  import graph, and a `@typescript-eslint/no-restricted-imports` block scoped to every file in
  that graph. The test is the complete check; the lint rule is the one that speaks before the
  file is saved. (Phase 6, CA-7.)
- Characterization tests live in `*-characterization.test.ts`, pin observed behavior, and mark
  quirks with `// QUIRK (docs/TECH-DEBT.md TD-…)`. They are never edited to make a behavior
  change pass; the behavior change gets its own commit that updates the pin deliberately.
- Structure-only and behavior-only changes never share a commit. A red test mid-refactor means
  revert, not debug.
- Run the suite under Node 22.23.2 before believing a red run.
