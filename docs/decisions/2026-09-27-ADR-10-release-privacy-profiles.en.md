## §2 — Decision (contract proposal)

**ADR-10-O1 (PROPOSAL) — a profile is a declared, testable configuration, not a marketing phrase.** `ReleaseProfile { id, egressPolicy: { allowedDestinationClasses[], setupPhaseAllowlist[], runtimeAllowlist[] | 'user_chosen_shown' }, telemetry: { local: 'off'|'opt_in', cloud: 'absent'|'opt_in'|'forbidden' }, modelPath, evaluatorPath, kvark: 'disconnected'|'connected_on_prem'|'forbidden', requiredReceipts[], allowedClaims[], forbiddenClaims[] }`. Every freeze candidate names the profiles it covers; the benchmark manifest (ADR-01 O3, brief §13.6) records `profileId`.

**ADR-10-O3 (PROPOSAL) — egress measurement as a receipt (FRD-12.5; AT-30 addendum).** Tool: recording of destinations (host:port + process) during the certify scenario on the **packaged** candidate; comparison against the profile's `setupPhaseAllowlist`/`runtimeAllowlist`; output = list of destinations, class, phase, count; an unknown destination = FAIL for P-LOCAL/OFFLINE, a "shown/allowed" check for P-BYOK. Tool in the repo **NOT FOUND** (grep `egress` yields the SSRF guard and the `executor-router` field) → Build-vs-Borrow record (BB-12/BB-13 addendum): candidates are OS-level (Windows `pktmon`/ETW in the certify script) or sidecar-level (an undici `Dispatcher` hook that logs `origin` — covers only the Node process, not Ollama/Tauri webview). Do not claim measurement before the tool exists.

**ADR-10-O4 (PROPOSAL) — one telemetry switch, one disclosure (corrects K3).** The Settings "anonymous telemetry" switch must: (a) control the local store (exists) **and** PostHog (`optOutPostHog/optInPostHog` called from the same handler, or PostHog default `opt_out_capturing_by_default: true` until the user turns it on); (b) onboarding shows what is sent (`onboarding_complete {template_id, persona_id, model}`) and to whom (`us.i.posthog.com`) **before** the first capture; (c) the release checklist records whether `VITE_POSTHOG_KEY` is baked into the candidate (hash `dist` for the string `phc_` — feasibility TO VERIFY) — if it is, the P-LOCAL egress allowlist **must** contain it or PostHog must be off by default. Recommendation for P-LOCAL/OFFLINE: cloud `absent` (the key is not baked in) — decided by the ratification of this ADR, not a separate DQ (ADR-INDEX §3).

**ADR-10-O5 (PROPOSAL) — models and binaries are components with provenance (A28; FR-OSS-04).** Inventory (repo/version/commit/hash/license/modifications/owner): Node runtime + npm, `better-sqlite3`, `sqlite-vec-windows-x64`, `onnxruntime-node`, Ollama zip (pins `managed-ollama-runtime.ts:160-184`), managed/recommended model digest (the receipt today proves `qwen2.5:0.5b`, not the reference target — F-UXM-06: explicit `certificateModel` vs `recommendedModel`), embedding model, reranker model (ADR-05 K1: bundle it or put it in the setup allowlist). `bundle-native-deps.mjs` places the LICENSE text alongside the binaries; a `THIRD_PARTY_NOTICES` generator over the `resources/node_modules` closure + manual entries for packages without a LICENSE file; SBOM (CycloneDX/SPDX — tool per BvB); certify gets an `Assert-True` group for both. **A change to the notices changes the installer SHA → new certification** (S1 OSS gate, correct).

**ADR-10-O6 (PROPOSAL) — the erasure/export boundary applies to every new store (A3; DIR-21; MIG-08).** Rule: a PR that introduces a persistent store (run store, checkpoints, `ToolAction`, WorkItems, override registry, capability requests, pairing) does **not pass** without (a) an export section (redacted: no vault values, no file contents in `args_json`), (b) an erase primitive bound to the same subject key/ledger (`erased_subjects`), (c) a "no secrets in export/prompt/trace" test (F-CAP-06 UNKNOWN whether it exists → new). Snapshot/rollback after erase re-applies the ledger (GDPR-H-04 in MIG-04/08); a sent email is not rolled back; `kvark:connection` deletion is a revocation. A technical test is **not** a legal certification (brief A3).
